## Gotchas the next agent should know

- The owner account predates Better Auth and has no `auth_user` row.
  Sign in works through the legacy fallback; a magic link creates the
  Better Auth record on first use. Do not remove the legacy
  `/v1/admin/login` route.
- Accounts created through Better Auth get a Flare `users` row with an
  unguessable placeholder password (legacy door shut for them).
- Better Auth wraps the raw D1 binding itself (`database: env.DB`);
  no `kysely-d1`. Its secret is the deployment secrets key
  (`SECRETS_KEY` env or D1 `secrets_key`). Cookie prefix `flare_auth`.
- Bundle after #31: 6.35 MB raw / 1.27 MB gzip (limit 10 MB).
- `Continue with GitHub` only works for the owner and allow-listed GitHub
  users; none are allow-listed on prod, so email is the way in.
- GitHub bridge (landing trains back on GitHub) is still a draft:
  [#12](https://github.com/everyai-com/flare-forge/pull/12). GitHub-hosted
  repos run in coordination mode (see `AGENTS.md`).
- The user's Mac disk hit 100% twice today and killed commands. Only
  the session's own scratch, npm caches and worktree temp dirs were
  deleted; check `df -h /` before deploys or recordings.
- `~/flare-actions` (the Actions monorepo) has other sessions'
  uncommitted work on branch `polish/agent-onboarding-on-forge`; this

## How to verify the state yourself

```bash
cd ~/flare-forge && git pull && npm run check -- --full       # types, lint, tests
curl -s https://flare-actions.everyai-com.workers.dev/v1/admin/status  # claimed, openRegistration
curl -s -o /dev/null -w "%{http_code}\n" https://flare-actions.everyai-com.workers.dev/v1/auth/get-session   # 200
```

Local end-to-end of the account flow on a throwaway D1:

```bash
cd ~/flare-forge && npx wrangler dev --port 8799 --persist-to /tmp/wr-ba
# then: POST /v1/auth/sign-up/email {name,email,password} → POST /v1/admin/auth/bridge → GET /v1/admin/status
```
